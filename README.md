# novel-distill

对小说正文做「文风指纹蒸馏 + 设定文档抽取 + 去 AI 味检测」。

**零依赖、纯 JS、不联网、不调模型。** 一份 core 双入口：命令行 CLI（主入口）+ 可选 MCP 服务器（供 agent 调用）。不依赖 SillyTavern、不依赖任何宿主。

---

## 它解决什么

你手头有一大堆正文（自己写的、或者你想模仿的），想问三个问题：

1. **这本书的文风长什么样？** —— 句长节奏、标点习惯、对话占比、比喻密度、口头禅/高频词、书页口头语…… 全变成可量化的指纹。
2. **这个世界里有什么？** —— 人物 / 地点 / 组织 / 物件四类实体自动抽出并按提及频次排序，直接当作设定文档的骨架。
3. **这段文字有多少 AI 味？** —— 纯规则、可解释地定位 AI 写作痕迹（列表体、解释性括号、空泛形容词堆叠、说教连接词、平行排比……），给 0–100 分。不调模型、不联网、不引入新 AI 味。

三项都是「诊断 + 报告」，不做改写（改写留待后续版本）。

> **v0.2 新增：语义层复审（两段式插件协议）** —— 规则只能抓「结构性」AI 味，抓不到「语义空洞」（句子通顺但只是情绪标签、抽象概括）。v0.2 增加语义层，但**仍不自己调模型**：插件定义「要问什么」+ 校验「答了什么」，模型由你（或宿主 agent）提供。详见下文。

## 快速开始

不需要安装，有 Node 18+ 即可。

```bash
# 三项全出（默认）
node cli.js 你的小说.txt

# 只看文风指纹
node cli.js 你的小说.txt --style

# 只要设定档案
node cli.js 你的小说.txt --entities

# 只要 AI 味检测
node cli.js 你的小说.txt --deai

# 输出 Markdown 报告到文件
node cli.js 你的小说.txt -o report.md

# 输出结构化 JSON（供程序/agent 消费）
node cli.js 你的小说.txt --json -o report.json

# 限制分析长度（默认全部，大文件建议限制）
node cli.js 你的小说.txt --max-chars 300000
```

### 参数一览

| 参数 | 说明 |
| --- | --- |
| `--style` | 只做文风指纹 |
| `--entities` | 只做设定抽取 |
| `--deai` | 只做 AI 味检测 |
| `--semantic` | 语义层复审第一段：跑规则 + 挑可疑片段 + 打印 prompt（需配合 `--deai`） |
| `--answers <json\|file>` | 语义层复审第二段：把模型答复（JSON 数组或文件路径）交给本工具校验并融合 |
| `--max-slices <n>` | 语义复审最多挑多少可疑片段（默认 12） |
| `--json` | 输出结构化 JSON 而非 Markdown |
| `-o, --out <file>` | 结果写入文件（默认打印到终端） |
| `--max-chars <n>` | 最多分析多少字符 |
| `--quiet` | 不打印头部信息 |
| `-h, --help` | 帮助 |

不传 `--style/--entities/--deai` 时，三项全出。`--semantic` / `--answers` 需与 `--deai` 一起用。

## 语义层复审（两段式插件协议，v0.2）

规则检测器抓的是**结构性**痕迹（列表体、括号解释、连接词……），抓不到**语义空洞**——句子读着通顺，却只是情绪标签、抽象概括，没有具体的人、物、动作。语义层补的就是这一块。

**关键：本工具自己不调模型。** 它是 agent 的插件，宿主 agent 本身有模型能力。插件只做两件事：① 定义「要问什么」 ② 校验「答了什么」。模型调用由宿主完成——插件永远不碰 API key、不联网、不知道用的是哪种模型。

### 两段式流程

```
stage1（挑片+提问）          宿主 agent 用「自己的模型」回答        stage2（校验+融合）
规则跑分 → 挑可疑片段  ──►  把 prompt 交给模型，拿回 JSON  ──►  逐条 quote 校验 → 与规则分并列
   pickSlices()                                                  parseAnswers()
```

**防幻觉红线**：stage2 会校验模型返回的 `quote` 必须能在原文对应区间内找到（去空白模糊匹配），否则**丢弃该条**并计入 `rejected`。这是防止模型「编造一个不存在的句子」当证据。

**融合口径**：规则分与语义分**并列展示，不加权成单一数字**。理由是可复核、可审计；「规则说干净但模型觉得有 AI 味」这个分歧本身就是诊断信息。结论按 `语义分 − 规则分` 的 ±25 分差判定方向。

### 用法一：MCP 两工具（宿主 agent 场景）

| 工具 | 说明 |
| --- | --- |
| `distill_deai_stage1` | 入参 `file` / `maxChars` / `maxSlices` / `json`。返回 `ruleScore`、`ruleIssues`、`suspectSlices`、`prompt`、`next` |
| `distill_deai_stage2` | 入参多一个 `semanticAnswers`（数组或原始字符串）。返回融合报告 |

宿主流程：调 stage1 → 拿 `prompt` 去问自己的模型 → 把模型答复原样传给 stage2（`file`/`maxChars`/`maxSlices` 须与 stage1 一致）。

### 用法二：CLI 手动降级（无宿主时）

```bash
# 第一段：打印 prompt，你手动贴给任意模型
node cli.js 小说.txt --deai --semantic --max-slices 6

# 第二段：把模型答复存成 reply.json，交给本工具校验并融合
node cli.js 小说.txt --deai --answers reply.json
```

`--answers` 既接受文件路径，也接受内联 JSON 字符串；答复可以是裸 JSON 数组，也可以是带 ```json 代码块和前后废话的原始回复（本工具会自动抠取）。

## 编码自动探测

中文小说常见 GB18030 / Big5 / UTF-8。本工具会自动探测，无需事先转码。

探测思路：用非致命解码器解一遍，再按「CJK 字符占比 × 100 + 可打印字符占比 × 20 − 替换符比例 × 1000 − 控制字符比例 × 800」打分，取最高分。实测对 GB18030 文本置信度 93~97，与 Big5 区分明显。

会顺带做：去 BOM、`\r\n` 归一为 `\n`、HTML 实体还原（如 `&#183;` → `·`）、全角空格转半角。

## 产物长什么样

### 文风指纹（部分字段）

```
段落：共 40562 段，平均 38.4 字，中位 35，P90 72
句子：共 49025 句，平均 31.4 字，中位 28
短句（≤8字）占比 11.1%；长句（≥40字）占比 29.8%
标点密度：逗号 69.9/千字，句号 29.7/千字
对话占比 11.9%；比喻 24.4/万字
```

### 设定档案（示例）

```
人物：兰希尔(774)  安格斯  鲁尔纳  兰莉儿  兰西亚  ……
地点：西风王国(84)  苍翠帝国(80)  提西岚山脉(26)  ……
组织：斯家(212)  赫利斯家(109)  疾电骑士团  埃梅纳斯学院  ……
物件：白兰十字剑  翠月之弓  湖光之盾  超凡药剂  ……
```

### AI 味检测

```
AI 味评分：100/100  —— 高
  [!] 列表体出现 N 处
  [!] 解释性括号 N 处
  ……
```

分级：≥60 高 / ≥30 中 / ≥12 低 / 其余 很干净。

实测对照：AI 味大纲样本 = 100/100「高」，人类网文正文样本 = 11~13/100「很干净」，拉开近 90 分，判别边界清晰。

## 作为 MCP 服务器使用（可选）

`mcp-server.js` 是一个零依赖的 MCP stdio 服务器（协议 `2024-11-05`），把三项能力暴露给 Claude Desktop / Cursor 等支持 MCP 的 agent。

暴露的工具：

| 工具 | 说明 |
| --- | --- |
| `distill_style` | 文风指纹 |
| `distill_entities` | 设定抽取 |
| `distill_deai` | AI 味检测 |
| `distill_all` | 三项一次出 |

每个工具接受：`file`（必填）、`maxChars`（默认 500000）、`json`（是否返回结构化 JSON）。

在 MCP 客户端里配置（示例）：

```json
{
  "mcpServers": {
    "novel-distill": {
      "command": "node",
      "args": ["/absolute/path/to/novel-distill/mcp-server.js"]
    }
  }
}
```

> 不装 MCP 也完全不影响使用——CLI 才是主入口。

## 设计原则

- **零依赖**：只用 Node 内置模块，不需要 `npm install`。
- **不联网、不调模型**：所有分析本地完成，不存在「用 AI 去 AI 味」的悖论。
- **可解释**：每一分扣在哪都能说清楚，不是黑盒打分。
- **一份 core、双入口**：CLI 和 MCP 复用同一套分析器，行为一致。
